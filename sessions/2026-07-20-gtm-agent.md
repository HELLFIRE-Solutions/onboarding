На момент цієї сесії gtm-agent (05) — єдиний модуль каталогу з реальним матеріалом: код Етапу 1 готовий, є `docs/architecture.md` і `docs/demo-ready-criteria.md` із зафіксованими рішеннями. "Наступні кроки" нижче).

## Фаза 1 — Контекст і навіщо (пройдено)

gtm-agent = модуль 1 у пріоритеті побудови: кваліфікація теплих лідів (LinkedIn/реферали, явно не масовий cold email — юридичний ризик у DACH), персоналізований аутрич, calendar booking. Обраний першим, бо одночасно продає і демонструє сам себе.

## Фаза 2 — Архітектурні рішення (пройдено)

Три рішення з `docs/architecture.md`, які варто вміти пояснити без підглядання:
1. **Оркестрація** — власний легкий оркестратор на Anthropic SDK, не LangGraph. Причина: пайплайн Етапу 1 лінійний (ingest → qualify → draft → [human approval] → send → track → log), LangGraph виправданий тільки коли з'явиться реальне розгалуження (Етап 2, per-client ICP-логіка).
2. **CRM = HubSpot Free** — нуль вартості при поточному обсязі лідів, є вбудований Meetings-інструмент (закриває booking без другої інтеграції), інтеграція за вузьким інтерфейсом (`integrations/hubspot.py`) щоб Етап 2 міг підміняти CRM.
3. **Legitimate interest gate** — `LegitimateInterestRecord` обов'язковий на кожен лід, перевірка **в коді** (`MissingLegitimateInterestError`), не тільки процесна вимога.

## Фаза 3 — Встановлення й конфігурація (частково пройдено)

```
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
pytest tests/   # 10 тестів
```

Встановлення й тестовий набір відтворювані без зовнішніх акаунтів — це саме те, що тести й повинні покривати (Claude API замокано в `test_orchestrator.py`). Реальне заповнення `.env` (`HUBSPOT_API_KEY`, `SMTP_*`/`IMAP_*`) — заблоковано: HubSpot-акаунт ще не створено, домен `hellfire.dev` очікується 2026-07-21.

## Фаза 4 — Керований прогін (частково заблоковано)

Робочий CLI-цикл: `import → qualify → list → approve → send → check-replies`. Кроки `import`, `qualify` (кваліфікація + драфт + HubSpot-синк), `list`, `approve` — код-готові й демонстровані на прикладі (`data/leads.example.csv`) навіть без реального HubSpot/домену через мок-режим тестів, але **живий** прогін на реальних лідах (критерії 1–6, 9 з `demo-ready-criteria.md`) чекає на реальний HubSpot-акаунт. Кроки `send`/`check-replies` (критерії 7–8) додатково чекають на верифікований домен `hellfire.dev`.

**Знахідка з onboarding-сесії:** сама сесія — перша перевірка, що demo-ready критерії з `docs/demo-ready-criteria.md` дійсно читабельні й дієві без додаткового контексту від того, хто модуль будував. Підтвердилось — Bob зміг пройти кроки 1–6 списку за самим документом.

## Фаза 5 — Запобіжники й межі (пройдено)

- Без активного `LegitimateInterestRecord` (або з виставленим `opt_out_at`) — агент відмовляється драфтити. Перевірено тестом, не лише документом.
- Жодне повідомлення не йде без явного `approve` від людини (`status: draft → approved → sent`, `send` бере лише `approved`).
- Явний non-goal: жодного LinkedIn-скрейпінгу чи авто-повідомлень — ліди заносяться в CSV вручну.
